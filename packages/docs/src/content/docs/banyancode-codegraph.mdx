# BanyanCode Code Graph

BanyanCode builds a polyglot code graph. Sixteen languages route through the tree-sitter parse path first: TypeScript / JavaScript / Python (node extraction plus `.scm` query edges with syntax-error detection) and rust / go / java / c / c++ / csharp / ruby / php / bash / zig / toml / yaml (AST-walk node extraction via the `langs/adapters/` mappings). Every tree-sitter language falls back to its regex parser when the wasm bundle is unavailable. The graph captures files, symbols, imports, calls, and Wave 1 structural edges (tests, routes, config mounts, etc.).

## Edge modes (`BANYANCODE_TS_EDGES`)

Derived edges are indexer-owned: `rebuildDerivedGraph` deletes and regenerates `calls` / `extends` / `references` / `imports` plus the structural cross-edges (`tested_by`, `configured_by`, `built_by`, `mounts`, `generated_from`) on every build. Set the environment variable to opt into parser-owned call edges:

- `BANYANCODE_TS_EDGES=derived` (default): exactly the derived lifecycle above — tree-sitter query edges (calls / yield / service_access) are discarded at index time and never reach the graph.
- `BANYANCODE_TS_EDGES=parser`: for files the tree-sitter parse path handled, the tree-sitter query edges (intra-file `calls`, `yield`, `service_access`) survive the derived pass. `imports` and all structural cross-edges stay derived; files parsed by the regex fallback (wasm unavailable) keep derived `calls` as usual.

Parse errors from the tree-sitter path (ERROR/MISSING nodes, wasm unavailable, exceptions) are recorded via `codegraph_parse_errors` and counted in the build report's `parseFailure` bucket; the file still indexes via the regex fallback.

## Ignore rules

The indexer skips:

- Default patterns: `node_modules`, `.git`, `dist`, `build`, `.sst`, `.opencode/`, `.banyancode/`, `*.db`, `*.db-wal`, `*.db-shm`
- `.gitignore` patterns from the project root
- `.banyancode/ignore` patterns (if present)

For workspace-specific exclusions — large scratch files, planning artifacts, vendored mirrors — drop a `.banyancode/ignore` at the workspace root listing one glob per line (gitignore syntax). Anything larger than the size cap, or that doesn't look like source code, is also skipped automatically and tallied in the build report's skip reasons.

## Building the code graph

### TUI

Run `/codegraph-build` from the prompt. A floating progress widget shows the current file and lets you cancel. The resolved DB path is shown in the widget.

### CLI

```bash
banyancode codegraph build --force
banyancode codegraph build --root ./packages/core --force
banyancode codegraph status
banyancode codegraph cancel
banyancode codegraph force-kill   # if cancel does not unblock a stuck build
banyancode codegraph path         # print .banyancode/banyancode.db location
```

### Agent tools

Agents can call `codegraph_build`, `codegraph_query`, `codegraph_callers`, `codegraph_dependents`, and `codegraph_impact`. Wave 1 also adds `codegraph_search`, structural `codegraph_find_*`, and seven `repo_*` tools — see the [BanyanCode overview](./banyancode.mdx).

## Querying

Use slash commands such as `/codegraph-search` and `/repo-find-subsystem`, or ask the agent to call the `codegraph_*` / `repo_*` tools directly. The **Codegraph Intel** sidebar panel keeps the last 8 queries visible during a session.

## Troubleshooting

### Build hangs or stalls

- Check `banyancode codegraph status` — if stuck at the same count, run `banyancode codegraph cancel` then `banyancode codegraph force-kill`.
- Ensure only one build runs at a time; a second `build` call is rejected while status is `running`.
- Verify BanyanCode is enabled (it is by default; only set `BANYANCODE_ENABLE=0` if you want to turn it off).

### Index fails

- Check that the root path exists and is readable.
- Verify `.banyancode/ignore` is not excluding necessary files.
- Ensure sufficient disk space for `banyancode.db`.

### Search returns no results

- Run `banyancode codegraph build --force` (or `/codegraph-build`) first.
- Try a more specific query or use `codegraph_query` for exact symbol matches.
