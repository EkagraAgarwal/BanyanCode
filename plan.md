## Steps

1. **Diagnose** (explore subagent, parallel): map the Linux install/upgrade pipeline with file:line evidence — the wrapper placeholder generation in `packages/opencode/script/publish.ts`, `postinstall.mjs` (hardcoded `bin/banyancode.exe` target), upgrade method implementations in `packages/opencode/src/installation/index.ts` (bun/npm/curl), `build.ts` per-platform dist package bin naming, the CI matrix + umbrella-package publish semantics (11 jobs publish the same `banyancode` npm name), and existing tests for install/upgrade/postinstall. Confirm whether the placeholder script lacks a shebang. Write findings to shared_memory `diagnosis:linux-install`.
2. **Research** (researcher subagent, parallel): (a) npm 11 `allow-scripts` semantics — what blocks the postinstall and what the recommended user-facing guidance is; (b) whether `bun install -g <pkg>` is valid bun syntax or must be `bun add -g <pkg>` (the upgrade runs `bun install -g banyancode@<target>` at `installation/index.ts:323`); (c) how upstream opencode's npm wrapper avoids/encounters this (bin shim resolving the platform package). Write to shared_memory `research:linux-install`.
3. **Fix** (coder subagent, parallel): 
   - (a) Placeholder wrapper: linux/darwin placeholder becomes a shebang'd `#!/bin/sh` script; windows stays cmd-compatible. Result: a skipped/blocked postinstall yields the actionable "postinstall script was not run" message instead of raw `ENOEXEC` when anything spawns the bin directly.
   - (b) Error message text covers npm 11 (`npm install -g --allow-scripts=banyancode` / `npm config set allow-scripts=banyancode --location=user`), bun/pnpm trustedDependencies, and the manual `cd node_modules/banyancode && node postinstall.mjs` fix.
   - (c) `postinstall.mjs` failure path carries the same hint.
   - (d) bun upgrade command corrected per research step 2 (use `bun add -g` if `bun install -g` is invalid).
   - (e) README install/upgrade section documents the npm 11 allow-scripts flow.
   - Keep the single `bin/banyancode.exe` shape (the umbrella tarball is published from any of 11 platform jobs — bin path must stay platform-invariant; only placeholder CONTENT may differ by platform).
4. **Tests**: unit tests for the placeholder generator (per-platform shebang/content) and the error message (contains `--allow-scripts` guidance). Run `bun typecheck` and `bun test` in `packages/opencode`.
5. **Commit + push** (lead): stage ONLY the fix files + `plan.md` (working tree contains unrelated pre-existing modifications and CRLF noise — leave them untouched). One commit per logical change. Push to `origin/dev` → auto-canary publish per AGENTS.md.
6. **Verify publish** (lead): confirm a publish.yml run exists for the pushed commit and `npm view banyancode@dev version` resolves to the new `YY.MM.PATCH-dev.<sha7>` build once CI completes.
